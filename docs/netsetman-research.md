# NetSetMan 静态研究与 NetSetGo 设计建议

研究日期：2026-11-17。范围：用户指定的 `D:\Program Files (x86)\NetSetMan\netsetman.exe` 与同目录帮助资源。

## 结论与证据边界

最适合借鉴的是“先保存方案、明确选择修改项、由用户触发应用、逐项显示结果”的交互流程。网卡、IP/DNS、多方案和应用反馈均取得帮助文档证据；REA 取得原生 PE 资源结构证据。没有运行目标程序，也没有实测任何网络修改。

本报告的“观察”仅表示读取到的文件、资源、字符串或帮助文档声明，不等于观察到程序执行。“推断”表示候选实现解释；“建议”是 NetSetGo 的独立设计选择；没有证据的行为标为“未知”。本轮未读取现有 `netsetman.xml`、Backup 或账户配置，未复制专有源代码或程序资源到实现工程，未进行许可绕过。

## 行为归纳

### 1. 网卡

**观察（E3，原文 250、253、256–257 行）：** 帮助声明网卡按名称和类型显示，启动时更新列表，并支持手动刷新。方案绑定的设备在跨机器或驱动更新后可能失效；文档描述按名称和 MAC 尝试重新关联。

**观察（E3，437、440 行）：** 文档列出启用、禁用、重启网卡，并通过多个子方案处理多网卡状态。

**观察（E4）：** UTF-16LE 字符串 `GetAdaptersAddresses` 出现在偏移 5,884,380 和 7,472,336；`Win32_NetworkAdapterConfiguration` 出现在 9,289,840。只确认字节存在。

**推断：** 程序可能使用 Windows 网络 API 和 WMI 获取或调整适配器信息；未建立导入表、调用者、可达性或具体执行路径。

**未知：** 设备标识的真实存储结构、重新关联优先级、禁用设备枚举覆盖、虚拟网卡过滤及重启失败恢复策略。

**建议：** NetSetGo 使用稳定设备标识保存绑定，并同时显示友好名称、类型和连接状态；列表提供刷新。设备不存在时保留方案并显示“网卡不可用”；名称或 MAC 匹配只能给出重新绑定候选，避免自动选错网卡。首版不必引入多网卡联动。

### 2. IP 与 DNS

**观察（E3，199、203、275–276、305 行）：** 文档区分“读取当前设置”“编辑保存方案”“应用选中设置”。未勾选的设置不参与应用；可以读取单项或全部当前设置。

**观察（E3，416–422 行）：** IP、网关和 DNS 为主界面核心字段；多个 IP/网关/DNS 以及 IPv6、路由、DNS 后缀、接口度量属于扩展配置。

**观察（E4）：** `EnableDHCP` 字符串见 UTF-16LE 偏移 9,277,016 和 9,425,272，以及 ASCII 偏移 9,290,644。

**推断：** 存在 DHCP 相关实现候选，但仅凭该字符串不能证明 DHCP 切换分支、默认 DNS 模式或副作用。

**未知：** IPv4 DHCP 与 DNS 自动获取是否独立建模、字段校验规则、空网关语义、多地址覆盖或合并规则、DNS 顺序处理及应用后回读方式。本地帮助文字未充分说明这些细节。

**建议：** 明确区分“保持不变”“自动获取”“手动设置”，分别建模 IPv4 和 DNS，避免空值隐含清除语义。主界面先覆盖 IPv4、子网掩码、网关、首选/备用 DNS；高级多地址与 IPv6 可后续增加。保存前完成格式校验，应用前展示变更摘要；这是独立设计，不声称复刻了原程序的字段规则。

### 3. 多方案管理

**观察（E3，190、222–234、289 行）：** 方案对应地点或场景；一个方案可包含多个按顺序执行的子方案。文档描述分组、创建、删除、搜索、复制粘贴、自动保存及摘要预览。

**观察（E3，207 行）：** 默认不会自动激活方案；自动切换是另行配置的能力。

**推断：** 方案编辑与实际网络状态应为两个独立状态域，保存方案不等于应用网络配置。

**未知：** 文件写入的原子性、备份和迁移规则、方案数量与当前许可版本的关系。本轮不分析许可实现，不将 Pro 功能视为当前安装可用功能。

**建议：** 首版提供新增、重命名、复制、删除、保存和“从当前网卡读取”。方案存储附版本号与稳定 ID，原子写入以降低文件损坏风险。先使用单层列表；仅在方案较多时加入分组或搜索。不要把选择方案和应用方案绑定成同一个动作。

### 4. 应用过程与反馈

**观察（E3，305–317 行）：** 文档说明由 Activate 或托盘菜单触发；对选中的设置显示进度、成功或失败；取消可能要等待当前动作结束。相同 IP 配置会跳过，并显示 Skip。日志区域显示完整错误信息。

**观察（E3，311、314 行）：** 相同 IP 配置的跳过可通过显式重启网卡强制重新初始化；某些设置需要等待才能生效，非网络设置还可能需要重启系统。

**观察（E3，889–901 行）：** 帮助说明修改网络和系统设置需要管理员权限，并描述其自身服务组件。这里只作为权限交互需求证据，不建议复制服务、签名或凭据存储机制。

**未知：** 部分失败时是否继续、实际取消粒度、超时、事务性回滚、恢复快照及应用后验证方式。帮助没有证明原程序具备自动回滚。

**建议：** 执行器按“待执行→执行中→成功/失败/跳过/取消”记录每一步。应用期间阻止重复启动同一操作；取消在步骤之间生效。区分“命令返回成功”和“回读配置符合预期”；部分成功必须单独呈现，不能只弹“完成”。错误信息保留步骤、错误码和可展开详情。自动回滚不作为首版承诺；如提供恢复功能，应独立验证其覆盖范围。

## 最小实现结构建议

以下为设计选择，不是反编译结果：

1. `ProfileStore` 负责方案读取、版本化保存；不调用系统网络写入。
2. `NetworkBackend` 负责网卡枚举、配置读取和单项应用；UI 不拼接命令。
3. `ApplyService` 生成变更计划、串行执行、发布步骤结果并回读状态。相同配置跳过；“重启网卡”保持显式操作。
4. 界面分为方案列表、网卡与字段编辑区、应用反馈区；保存和应用使用不同按钮。

先将网卡刷新、单网卡 IPv4/DNS、方案增删改复制、逐项反馈做完整。托盘、自动切换、复杂多网卡编排、常驻服务和高级路由均可后置，避免首版承担原产品全部范围。

## 建议验收场景

这些是 NetSetGo 后续验证要求，本轮均未执行系统修改：

- 编辑或切换选中的方案不会立即改变系统配置。
- 网卡被移除后，方案仍可编辑，应用给出明确原因。
- IP 自动获取与 DNS 手动配置可独立表达；未选择修改的字段保持不变。
- 与当前配置相同的步骤显示跳过；显式重启单独提示。
- 无管理员权限、单步骤失败、取消及配置尚未生效可区分呈现。
- 方案文件损坏或版本不支持时提供错误，避免静默覆盖。
